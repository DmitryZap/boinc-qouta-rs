# Описание проекта
Система распределённых добровольных вычислений по аналогии с BOINC, но
**полностью децентрализованная** (без центрального сервера) и с собственной
**экономикой** на самописном блокчейне. Целевые задачи — машинное обучение
(распределённое обучение, инференс) и математические вычисления.

Каждая вычисленная задача сжигает валюту у автора задачи и начисляет её
исполнителю. Стоимость задачи измеряется фактической вычислительной работой,
поэтому экономика естественно отражает, какие задачи дороже других.

Применение: разворачивается и локально внутри организации (частный кластер),
и глобально как BOINC (публичная добровольная сеть).

# Архитектура
Один бинарь, два фронта запуска: десктоп GUI (`src/bin/gui.rs`, eframe) и
headless CLI (`src/bin/cli.rs`, для серверов и скриптовых тестов). Узел может
быть координатором и/или воркером.

## Реплицируемая машина состояний
Состояние сети (балансы, проекты, задачи, репутация) реплицируется на каждом
узле. Изменения выражаются операциями `LedgerOp` (`ops.rs`), которые узлы
применяют через `Network::apply_op` в **одинаковом порядке** → все сходятся к
байт-идентичному состоянию. Id проектов/задач выделяются детерминированно при
применении (счётчики идут синхронно, т.к. порядок операций одинаков везде).

## BFT-консенсус (`consensus.rs`)
Каждый узел держит `ConsensusEngine`. Раунд на высоту H = `chain.next_index()`:
proposer (round-robin `validators[H % n]`) собирает блок, подписывает, рассылает
`Propose` + свой `Vote`; валидаторы голосуют; при достижении кворума голосов
блок запечатывается сертификатом и аппендится. Чистая логика, без I/O —
`actor.rs` релеит `ConsensusMsg` по gossip-мэшу с дедупликацией (seen-set).
Цепочка персистится между переподключениями.

## Консенсус по результатам задач (`network.rs`)
Задача назначается нескольким исполнителям с арендой (lease) и таймаутом.
Исполнители шлют digest результата; принимается digest, набравший
репутационно-взвешенный кворум. Истечение аренды → штраф + возврат задачи.

## Исполнение (`executor.rs`, `sandbox.rs`, `pyenv.rs`, `estimator.rs`)
Payload — base64 (url-safe) Python: префиксы `python:` / `python-gpu:`.
**Docker удалён.** Python исполняется во встроенном интерпретаторе через PyO3
(`Python::attach`). Изоляция — smolagents `LocalPythonExecutor`: allowlist
импортов, блок доступа к субмодулям, hard-cap операций (останавливает бесконечные
циклы без kill), wall-clock backstop.
`pyenv.rs`: bundled python-build-standalone рядом с бинарём (`PYTHONHOME`) +
writable venv (smolagents + разрешённые пакеты) в data-dir; fallback на системный
Python >=3.10. `estimator.rs`: pre-estimate стоимости по исходнику + измерение
фактической стоимости по счётчику операций интерпретатора.

## Identity (`identity.rs`)
Ed25519 (подпись handshake-nonce и блоков консенсуса) + X25519 (шифрование
результата для владельца проекта). Ключ — `~/.boinc-quota/identity.json`.
ВАЖНО: каждый локальный инстанс должен иметь свой identity (`--identity` у CLI),
иначе узлы делят аккаунт и набор валидаторов схлопывается.

## Сеть (`actor.rs`, `protocol.rs`)
`NetworkActor` на Tokio. GUI ↔ актор: `AppCommand`/`AppEvent` (mpsc). Между
узлами: `P2pMessage` (line-delimited JSON по TCP) — `PeerRequest`/`PeerResponse`
+ `ConsensusMsg`. Состояние координатора персистится в
`<data_local_dir>/boinc-quota/coordinator-state.json`.

## Модули
`actor` сеть/мэш · `app` GUI-логика · `blockchain` блоки+SHA-256+BFT-сертификат ·
`consensus` BFT · `ops` LedgerOp · `network` доменная модель + task-консенсус ·
`executor`/`sandbox`/`pyenv`/`estimator` исполнение · `identity` ключи ·
`protocol` сообщения · `model` типы id.
